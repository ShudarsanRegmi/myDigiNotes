# Routing Interview Definitions

These are phrased so you can **say them directly in an interview** without sounding like you're reciting a textbook.

## 1. Routing

> **Routing is the process of determining the best path or next hop for delivering packets from a source network to a destination network.**

---

## 2. Routing Table

> **A routing table is a data structure maintained by a router that contains information about reachable destination networks, their next hops, outgoing interfaces, and other route-related information.**

---

## 3. Route

> **A route is information that tells a router how to reach a particular destination network, typically including the destination prefix, next hop, and outgoing interface.**

---

## 4. Next Hop

> **The next hop is the immediate router or gateway to which a packet is forwarded on its way toward the destination.**

Important distinction:

> The next hop is **not necessarily the final destination or the entire path**.

---

## 5. Longest Prefix Match

> **Longest Prefix Match is the process of selecting the most specific route when multiple routing-table entries match a destination IP address.**

Example:

```text
10.0.0.0/8
10.10.0.0/16
10.10.20.0/24
```

For `10.10.20.5`, `/24` wins because it matches the most bits.

---

## 6. Routing Metric

> **A routing metric is a value used by a routing protocol to measure the desirability or cost of a path and select the preferred route.**

Examples:

```text
RIP  → Hop count
OSPF → Cost
```

---

## 7. Administrative Distance

> **Administrative Distance is a value used by a router to determine which routing source should be trusted when the same destination is learned through different routing protocols or sources.**

Key distinction:

> **Metric compares paths within a routing protocol; Administrative Distance compares routing sources.**

---

# Routing Algorithm Definitions

## 8. Distance Vector Routing

> **Distance Vector is a routing approach where routers learn the distance or cost to destinations from their neighbors and iteratively select the best route based on that information.**

Good follow-up phrase:

> "The router does not need a complete view of the network topology."

---

## 9. Link State Routing

> **Link State is a routing approach where routers advertise information about their connected links, build a database representing the network topology, and independently calculate the best paths through that topology.**

---

## 10. Path Vector Routing

> **Path Vector is a routing approach where routers advertise reachable networks along with information about the path taken to reach them, allowing routers to select paths based on both path information and routing policy.**

This is the definition you want for BGP.

---

## 11. Routing Protocol

> **A routing protocol is a protocol that allows routers to exchange routing information and dynamically determine the best paths to destination networks.**

---

# RIP / OSPF Definitions

## 12. RIP

> **RIP is a distance-vector interior gateway routing protocol that uses hop count as its routing metric, with a maximum usable distance of 15 hops.**

If they ask for one more detail:

> "It is simple but has limited scalability and relatively slow convergence."

---

## 13. OSPF

> **OSPF is a link-state interior gateway protocol that builds a topology database and uses the Shortest Path First algorithm to calculate routes based on link cost.**

---

## 14. LSDB

> **The Link-State Database is the database maintained by an OSPF router containing the link-state information used to represent the topology of its OSPF area.**

---

## 15. LSA

> **An LSA, or Link-State Advertisement, is information generated by an OSPF router describing its links or other routing information and distributed to other OSPF routers.**

Simple mental distinction:

```text
LSA = information
LSDB = collection of that information
```

---

## 16. SPF

> **SPF, or Shortest Path First, is the calculation performed by a link-state router to determine the lowest-cost paths through the topology represented in its LSDB.**

---

## 17. OSPF Area

> **An OSPF area is a logical subdivision of an OSPF routing domain used to limit the scope of detailed topology information and improve scalability.**

---

## 18. OSPF Area 0

> **Area 0 is the OSPF backbone area that provides the central connectivity for inter-area routing.**

---

## 19. ABR

> **An Area Border Router is an OSPF router that connects one OSPF area to another, typically connecting a non-backbone area to the backbone.**

---

## 20. ASBR

> **An Autonomous System Boundary Router is an OSPF router that introduces routing information from an external routing domain or source into OSPF.**

Don't confuse:

```text
ABR → connects OSPF areas
ASBR → connects OSPF to external routing information
```

---

## 21. DR

> **A Designated Router is an OSPF router elected on a multi-access network to reduce the number of OSPF adjacencies and simplify the exchange of link-state information.**

---

## 22. BDR

> **A Backup Designated Router is the standby OSPF router that can take over the DR role if the current DR fails.**

---

# BGP Definitions

## 23. BGP

> **BGP, or Border Gateway Protocol, is a path-vector routing protocol used to exchange network reachability information between Autonomous Systems and select routes based on routing policies and path attributes.**

This is probably the **single most important definition** in this section.

---

## 24. Autonomous System

> **An Autonomous System is a collection of networks and routers under a common administrative control that follows a common routing policy toward other networks.**

---

## 25. ASN

> **An Autonomous System Number is a unique number used to identify an Autonomous System in inter-domain routing protocols such as BGP.**

---

## 26. eBGP

> **eBGP, or External BGP, is BGP used to exchange routing information between routers belonging to different Autonomous Systems.**

---

## 27. iBGP

> **iBGP, or Internal BGP, is BGP used to distribute BGP routing information between routers within the same Autonomous System.**

---

## 28. AS_PATH

> **AS_PATH is a BGP path attribute that records the sequence of Autonomous Systems through which a route has been advertised. It is used for path selection and for preventing routing loops.**

Excellent interview answer because it gives **both purposes**.

---

## 29. BGP Attribute

> **A BGP attribute is information associated with a route that describes characteristics of that route and influences BGP's path-selection process.**

Examples:

```text
AS_PATH
LOCAL_PREF
MED
NEXT_HOP
ORIGIN
COMMUNITY
```

---

## 30. LOCAL_PREF

> **LOCAL_PREF is a BGP attribute used within an Autonomous System to indicate which outbound path the AS prefers. A higher value is generally preferred.**

Think:

> **"Which exit should my AS use?"**

---

## 31. MED

> **MED, or Multi-Exit Discriminator, is a BGP attribute used to suggest to a neighboring Autonomous System which entry point into the advertising AS is preferred when multiple links exist. A lower value is generally preferred.**

Think:

> **"Which entry should the neighboring AS use to reach me?"**

---

## 32. NEXT_HOP

> **NEXT_HOP is a BGP attribute that identifies the IP address of the next-hop router that should be used to reach the advertised destination.**

---

## 33. BGP Best Path

> **BGP best-path selection is the process of comparing available BGP routes using their attributes and routing policies to select the preferred route for a destination.**

Important:

> **BGP does not simply choose the route with the shortest AS_PATH.**

---

## 34. BGP Community

> **A BGP community is a tag attached to a route that allows routers to classify routes and apply predefined routing policies to them.**

Think:

```text
Tag the route
    ↓
Recognize the tag
    ↓
Apply policy
```

---

# Routing Scope Definitions

## 35. IGP

> **An Interior Gateway Protocol is a routing protocol used to exchange routing information within a single Autonomous System.**

Examples:

```text
RIP
OSPF
IS-IS
EIGRP
```

---

## 36. EGP / Inter-Domain Routing

> **Inter-domain routing refers to routing between different Autonomous Systems. BGP is the standard protocol used for this purpose on the Internet.**

A useful nuance:

> **BGP is technically an EGP, but "EGP" can also refer specifically to the older Exterior Gateway Protocol that preceded BGP.**

So in an interview, saying **"BGP is an inter-domain routing protocol"** is usually the cleanest phrasing.

---

# Convergence and Loop Definitions

## 37. Convergence

> **Convergence is the process by which routers update their routing information after a topology change and reach a consistent state where they have the correct routes again.**

---

## 38. Routing Loop

> **A routing loop occurs when packets are repeatedly forwarded between routers without making progress toward their destination.**

---

## 39. Count-to-Infinity

> **Count-to-infinity is a distance-vector routing problem where routers continuously increase the metric of a failed or unreachable route because they incorrectly learn the route from one another.**

---

## 40. Split Horizon

> **Split Horizon is a distance-vector loop-prevention technique in which a router does not advertise a route back through the same interface from which it originally learned that route.**

---

## 41. Poison Reverse

> **Poison Reverse is a variation of split horizon where a router explicitly advertises a learned route back to the source with an infinite metric, indicating that the route is unreachable through that router.**

---

# Control Plane / Forwarding Definitions

## 42. Control Plane

> **The control plane is responsible for learning network topology and routes and deciding which routes should be installed for forwarding.**

---

## 43. Data Plane

> **The data plane is responsible for actually forwarding packets according to the forwarding information generated by the control plane.**

---

## 44. RIB

> **The Routing Information Base is the routing table used by the control plane to store and select routes learned from different sources.**

---

## 45. FIB

> **The Forwarding Information Base is the optimized forwarding table used by the data plane to make packet-forwarding decisions efficiently.**

---

The trick is **not** to memorize these as isolated textbook definitions. For each one, know the one conceptual question it answers:

```text
LPM          → Which matching route is most specific?
Metric       → Which path does this protocol prefer?
AD           → Which routing source do I trust?

DV           → What distance did my neighbor advertise?
LS           → What does the topology look like?
Path Vector  → What AS path exists and what policy applies?

RIP          → Simple DV using hop count
OSPF         → LS routing using topology + cost
BGP          → Inter-domain path + policy routing

AS_PATH      → Which ASes did this route traverse?
LOCAL_PREF   → Which exit should my AS prefer?
MED          → Which entry should my neighbor prefer?

RIB          → What routes did the control plane select?
FIB          → How do I actually forward the packet?
```

That last style of thinking will make your answers sound **understood rather than memorized**, which is exactly what you want in a technical interview.
